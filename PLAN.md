## 1. Lock the task specification before modeling

**Confirmed task formulation:** Each example contains a news article's text and an accompanying image. Predict zero or more framings conveyed by the **image** from the shared taxonomy of 14 generic framings (Card et al., 2015). This is multilabel classification. In Subtask 2a, human-labeled framings for the article text are unavailable; in Subtask 2b, they are available. The article text is context in both variants, but image framing labels remain the target. In 2b, do not treat text framing labels as image ground truth. The task covers Bulgarian, English, European Portuguese, and Russian. Participants can choose any subtask-language pairs and may train across languages.

**Confirmed data and output contract:** Articles are UTF-8 `.txt` files; when present, the title occupies line 1, line 2 is empty, and the body begins on line 3. Images may be JPG/JPEG, PNG, WebP, or GIF. The image gold file and system response are tab-separated: `file-name<TAB>framing-dimension[<TAB>framing-dimension...]`, one line per image. The framing field remains empty for images with no frame. At test time, organizers provide a file listing image names; the response is one file using the gold-label syntax. Exact label spelling must come from `framing-labels.txt`. The official score is multilabel **micro-F1**; macro-F1 and other scores are secondary. The task page says the scorer uses a `None` label for unframed cases, but its Subtask 2 text says "no framing in text"; verify the image scorer's exact treatment of empty rows before implementing it.

**Still to verify from starter kit/scorer:** all 14 exact label strings, image-to-article mapping, the 2b gold text-label format and availability at test time, scorer rules for `None`, whether both variants have separate submission endpoints, permitted external data/models, test validator, final dates, and system paper/code requirements. The published page says detailed submission instructions will follow. Describe observable input/output first, then reason about image cues, text-image agreement or tension, annotation ambiguity, source effects, and shortcuts.

## 2. Dataset audit and selective EDA

Use the supplied files without modifying raw data. The task page promises labeled training data and an **unlabeled development set** scored through an online submission site; the linked ZIP is trial data with articles and gold annotations in four languages. Record sample and split counts; image-frame frequency, per-example label count including zero-label cases, and frame co-occurrence; missing/corrupt images or article text; exact and near duplicates; image dimensions/aspect ratios; unusually short or long articles; language/source distributions; and overlap between splits. For images with embedded text, measure OCR coverage and text length. If text-frame labels are available, compare their distribution and agreement with image frames, without assuming equivalence. Keep a fixed manifest of valid examples and any exclusions.

Select roughly 4–8 task-relevant feature groups. Initial candidates are (1) geometry and layout, (2) color/contrast and brightness, (3) image quality and compression, (4) OCR text presence/density, (5) visual object or scene content through pretrained embeddings, (6) article-image semantic similarity, and (7) source/template families. Each selected group must answer a question about framing or likely model behavior. Report associations with image frames and consider confounding from news sources or repeated templates. For every reported pattern, write an **observation**, a cautious **interpretation**, and a **modeling implication**. Save only useful, self-explanatory plots in one EDA PDF; titles, axes, units, and legends replace traditional figure captions in that PDF.

## 3. Reproducible Assignment 1 baselines

Create a labeled internal validation split from the training set, stratifying by frames and language where feasible. The organizer's development labels are withheld, so use the online leaderboard for a limited final check rather than threshold search. Avoid choosing features, thresholds, or hyperparameters from the test set. Group article-linked images and near-duplicate templates before any internal split if leakage is possible. Record random seed, package versions, image preprocessing, missing-data handling, and model settings.

**Classical baseline:** extract interpretable image features (for example, color histograms, HOG/edge statistics, layout, and OCR-derived counts). Fit one regularized binary logistic-regression or linear-SVM classifier per image frame. This permits several positive labels or an all-negative result. In 2a, consider article TF-IDF as context, while also reporting an image-only version to expose text shortcuts. In 2b, add the gold text-frame vector as an explicit feature and compare it against the 2a setup. Tune per-label or shared thresholds only on the labeled internal validation data. Inspect valid coefficients or feature contributions and connect them to the EDA.

**Pretrained baseline:** use a suitable vision encoder such as CLIP or a pretrained ViT to extract frozen image embeddings, then train a multilabel supervised head on the same split. State clearly that the encoder is frozen. If allowed, add article text embeddings for 2a and the gold text-frame vector for 2b, with an image-only comparison to check whether the model is recognizing frames in the image. Keep fine-tuning and larger architectures for later assignments unless needed to obtain a functioning baseline.

Evaluate both variants with the organizer's multilabel micro-F1 scorer and reproduce its `None` handling. Explain micro-F1 using aggregate true positives, false positives, and false negatives; report complementary macro-F1 and per-frame precision/recall to expose rare-frame failures. Inspect co-occurrence errors, zero-label errors, and representative false positives/negatives. Compare 2a with 2b to quantify the value of gold text framings while checking cases where article framing and image framing differ. Report all attempted runs, including failures, without turning test data into development feedback.
